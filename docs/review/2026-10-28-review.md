# Application review — 2026-10-28

Reviewed the application’s accounting, daily policy transitions, SQLite persistence,
device synchronization, authentication and API boundaries, Timekpr adapter,
CLI, Telegram/Matrix delivery, desktop countdown/notifications, parent web UI,
and Nix service wiring. This is a bounded review, not proof that no bugs remain.
Dependencies were inspected for adapter contracts but not modified.

## Confirmed defects and corrections

| Area | Defect | Correction and regression evidence |
| --- | --- | --- |
| Midnight accounting | The undated native counter could charge yesterday’s usage to a new day before Timekpr reset it. | Read the saved counter with its date; reject invalid/changing snapshots and observations crossing midnight. Tests cover delayed resets, restart, year/DST boundaries, and new-day allocation. |
| Remaining-time edits | A zero-clamped balance hid overrun, so setting 90 minutes could leave less than 90. | Calculate the new total from recorded usage plus requested remaining time. Backend, standalone and browser tests cover overdrawn usage and retries. |
| Parent refresh | A successful mutation’s refresh was dropped while an older refresh was running. | Coalesce overlapping refreshes and await a new snapshot. A browser test holds the old response across the mutation. |
| Live policy | Activity masks, inactive tracking and lockout settings were only rendered at startup. | Apply and verify these settings through D-Bus, avoiding unchanged writes and preserving consumption. Adapter and real-Timekpr VM tests cover updates. |
| Parent status | Available budget could be presented as allowed access outside the schedule, or exhausted during homework. | Use the shared policy decision for phase, schedule and homework status. |
| Homework countdown | Unmetered access could display a countdown extending past homework into an already-exhausted metered period. | Re-evaluate at the homework boundary. |
| Expired delivery | Reconnecting after midnight could mark yesterday’s unapplied daily command applied. | Expire daily receipts before processing acknowledgements. |
| Persistent delivery | Mute/unmute/unblock and multi-day blocks were all assigned midnight delivery expiry. | Match expiry to the command’s actual scope, including older queued receipts. |
| Backend transport | HTTP rejections were caught as generic connection failures; malformed error bodies and SSE values could escape expected handling. | Preserve rejection status, validate event objects and bound the complete event payload. |
| Input boundaries | Invalid timezones and malformed device request/application fields could produce server errors or invalid stored state. | Validate consumed report fields and timezone-aware timestamps before persistence. |
| Cookie mutations | DELETE routes omitted the origin check applied to other mutations. | Enforce the same origin boundary for DELETE; rejected requests leave links intact. |
| Offline backlog | Old unacknowledged reports could fill the batch or fall outside the server’s accepted interval and block current synchronization. | Prioritize current reports, retain old local history and only submit dates within the accepted interval. |
| Web controls | Inactive tracking had an inverted label; console-login restrictions appeared remotely editable; indefinite blocking was offered although rejected by the API. | Correct the label, show console restrictions as host-managed and expose supported block durations. |
| External sign-in | Reading disabled browser storage aborted the OIDC callback before exchanging the code. | Treat language storage as optional; browser coverage includes blocked storage. |
| Logging | Timekpr debug output had no rotation, allowing very large logs. | Default to informational logging and configure daily rotation with a size trigger and seven retained files. |

## Deployment and evidence limits

These are repository changes. No production deployment, database repair, log deletion,
or user-budget adjustment was performed. The existing SSH session cannot read the
privileged accounting databases or activate the fixes without sudo access.

The bounded production log inspection found successful synchronization around the
reported repeated edits. It did not expose the individual submitted amounts and
resulting balances. The reproduced accounting and refresh defects must not be
presented as a reconstruction of all three live submissions.

Physical suspend, compositor behavior, external OIDC/Telegram/Matrix accounts and
the actual household’s selected process masks still need deployment verification.
The automated tests use isolated state and synthetic credentials. Existing erroneous
historical usage is retained; correcting today’s remaining time after deployment
does not rewrite that history.
